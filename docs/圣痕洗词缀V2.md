# 圣痕洗词缀（智能版）

通过角色属性、武器类别和攻击力目标自动选择词缀，与原正则版任务并存。

## 使用方法

先在游戏中点一次「词缀重构」，停在同时显示旧、新词缀和「保留旧词缀 / 写入新词缀」按钮的**重构结果页**，再启动任务。

- **直接洗词缀**：从普通重构页进入结果页。
- **词缀锁洗词缀**：先在定向重构页锁好要保留的一条，再进入结果页，并在任务设置中确认使用词缀锁。

| 设置 | 说明 |
| --- | --- |
| 洗词缀模式 | 直接洗词缀 / 词缀锁洗词缀 |
| 确认使用词缀锁 | 锁模式必须选「是」，默认「否」 |
| 单条高攻 | 默认开启；任意一条有效攻击力达标也结束，锁模式忽略此项 |
| 单条达标值 | 默认 22.9 |
| 角色属性 | 生物 / 机械 / 异能 / 量子 / 虚数 / 星尘 |
| 武器类别 | 按菜单中的武器分组选择 |
| 目标总攻击力 | 两条有效攻击力之和，默认 42 |
| 重构次数上限 | 最多自动重构 500 次，不含启动前手动重构的一次 |

最后一次自动重构得到的候选仍会被检查，更优时会写入；达到次数上限后不会再生成一批未检查的候选。

## 择优规则

只统计对所选角色有效的攻击力：

| 词缀 | 有效条件 |
| --- | --- |
| 属性角色攻击提升 | 属性与所选角色一致 |
| 武器角色攻击提升 | 识别到的武器均属于所选武器组 |
| 无条件攻击提升 | 任何角色均有效 |
| 已知非攻击词缀 | 按 0 计，例如生命、会心、暴击伤害 |
| 无法确认的词缀 | 标为存疑，不能据此覆盖旧词缀 |

旧词缀已达标时保留并结束；新词缀总攻击力更高时先写入保底。普通模式开启单条高攻后，新侧最高单条达到阈值且超过旧侧最高单条，也可写入。单条比较使用两侧最高值，与所在行无关。

新词缀达标时，写入并确认返回对应主页后立即结束，不再额外重构。未达标则继续：

- 普通模式可在结果页点「再次重构」。
- 锁模式先保留或写入，返回定向重构页后再重构。

## 识别与停止条件

新旧两侧从同一张截图读取。一条词缀被 OCR 分成多个文本块时，按阅读顺序拼接，避免丢失条件文字。保留常见的数字、属性易混字和武器别名处理。

每条词缀必须带数字及足够的中文文本。只将明确的非攻击词缀计为 0；类型、条件或数值无法确认时，整侧不可用于择优。

锁模式逐行比较**规范化后的完整文本**，不以「类型 + 数值」推断条件相同。只有一条相同，且锁定行位置未发生变化，才继续。两条都变化、都不变或无法可靠识别时，在当前页面复核；仍无法确认就停止。文本比较只能核对锁定行的一致性，仍需用户预先正确设置锁。

未达标而继续重构时，下一轮旧词缀还需与上一轮保留或写入的完整词缀一致。所有复核最多尝试 `OCR重试次数` 次，默认 3 次；重试期间不点击按钮、不消耗材料。界面未按预期跳转、点击失败或用户停止任务时，也不再重构。

达标写入后通过返回主页确认流程结束，不为复核词缀额外消耗一次材料；游戏中的实际保存效果仍建议在首次使用时检查。

## 开发维护

- UI 选项覆盖入口「洗词缀V2」的 `attach` 字段，运行时通过 `context.get_node_data()` 读取。默认值只在 pipeline 中维护。
- `attach.nodes` 保存面板、按钮和页面标记的节点映射；ROI、OCR 匹配文本在对应节点中配置。
- 按钮调用 `context.run_task()`，由 MaaFramework 完成识别、重试和点击。使用识别框作为点击区域，动画等待由 `post_delay` 控制。
- 业务规则位于 `agent/custom/utils/AffixRules.py`；循环与复核位于 `agent/custom/action/AffixRerollV2.py`。
- `attach` 需要 MaaFramework 5.0 及以上；本项目其他 pipeline 也已使用 5.x 功能。

安装项目依赖后，可在仓库根目录运行：

```shell
python -m unittest discover -s tests -p "test_affix*.py"
python tools/check_resource.py ./assets/interface.json
```

这些检查覆盖规则、模拟界面流程及资源加载，不代替游戏实机验证。
